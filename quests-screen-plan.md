# План переработки экрана «Квесты»

## Кратко о задаче

Переработать мобильный экран «Квесты» в существующем прототипе: убрать блок доступных квестов и раскрыть текущий активный квест подробностями об ошибках по его параметру, практическими рекомендациями и мок-карточками внутренних обучающих материалов. Для примера параметра используется «Закрытие».

**Затрагиваемый экран:** `screens/quests.html`  
**Референс ошибок:** раздел «Что пошло не так» в `screens/call-detail.html`  
**Текущее состояние:** экран содержит баланс, один активный квест, библиотеку доступных квестов, историю выполненных квестов и диалог взятия квеста.

## Цели и границы

### Цели
- Сфокусировать экран на уже принятом квесте и его выполнении.
- Показать, какие конкретно ошибки по параметру мешают выполнить условие.
- Дать сотруднику следующий практический шаг: рекомендацию и обучающий материал.
- Сохранить понятность прогресса и замороженного баланса.
- Сгенерировать мок-данные для заголовков обучений.

### Вне объёма
- Пересмотр правил начисления/заморозки очков и логики прогресса.
- Изменение экрана разбора звонка или общей аналитики.


## Предлагаемая структура экрана

1. **Шапка «Квесты»** — сохранить текущую навигацию.
2. **Баланс** — оставить активный и замороженный баланс с кратким пояснением механики.
3. **Активный квест** — название, параметр, измеримое условие, прогресс, число оставшихся успешных действий и замороженная сумма.
4. **Ошибки по параметру** — список событий, связанных только с параметром активного квеста; по визуальному формату ориентироваться на карточки раздела «Что пошло не так» в `call-detail.html`.
5. **Как улучшить результат** — мок-рекомендации и эталонные фразы, связанные с ошибками по параметру «Закрытие».
6. **Материалы компании** — три демонстрационные карточки обучения с названием, форматом и описанием; URL отсутствует, нажатие не открывает ничего.
7. **Выполненные квесты** — сохранить историю компактным блоком ниже подробностей активного квеста.
8. **Нижняя навигация** — оставить без изменений.

**Демо-ограничения:** экран всегда показывается с активным квестом; сценарий отсутствия активного квеста не проектировать. Ошибки показывать за последние 7 дней: сначала 5 карточек, затем действие «Показать ещё». Переход из ошибки в звонок/таймкод не требуется.

## Пошаговый план реализации

### 1. Удалить сценарий выбора нового квеста
- Удалить заголовок и список «Доступные».
- Удалить обработчики взятия квеста и диалог подтверждения заморозки баланса, если они больше нигде не используются.
- Удалить связанные данные `LIB` для квестов, которые служили только предложениями.
- Сохранить обработку активного квеста, баланса и завершения квеста.
- Не добавлять пустое состояние без активного квеста: оно не входит в демо-сценарий.

### 2. Уточнить данные активного квеста
- Явно связать квест с параметром аналитики: `parameter: "Закрытие"`.
- Для демо оставить условие «Этап „Закрытие“ ≥ 7 в 5 звонках подряд» и показать прогресс/остаток до цели.
- Сохранить видимыми прогресс, остаток до цели и сумму замороженных очков.
- Выбирать для списка только ошибки по параметру «Закрытие», зафиксированные в последние 7 дней.
- При первом отображении показывать 5 карточек. По нажатию «Показать ещё» добавлять следующую порцию карточек (до 5 или все оставшиеся); скрывать действие, когда записи закончились.

### 3. Добавить список ошибок по параметру
- Использовать структуру карточек, знакомую по «Что пошло не так» в отдельном звонке, но убрать элементы, не применимые к квесту.
- Для каждой ошибки показывать:
  - этап/подтип параметра и короткий заголовок ошибки;
  - конкретное наблюдение — что не сделал или сделал неверно сотрудник;
  - мок-цитату из звонка;
  - объяснение, какое правило параметра «Закрытие» нарушено.
- Не смешивать ошибки из других параметров, например приветствия или квалификации.
- Ошибки и цитаты — демонстрационные; не показывать таймкод и не делать карточки переходами в звонок.
- Пустой список ошибок допускается как состояние внутри активного квеста: коротко объяснить, что за последние 7 дней ошибок по параметру не найдено.
- Список за последние 7 дней: 5 карточек изначально; кнопка «Показать ещё» раскрывает следующую порцию, пока не показаны все мок-записи.

### 4. Добавить рекомендации
- Создать связанные мок-рекомендации и эталонные формулировки; владелец/утверждающий для демо не требуется.
- Для примера по «Закрытию» показать короткий приём на следующий звонок: зафиксировать решение клиента, договориться о конкретном следующем шаге и сроке, проверить понимание.
- Связать каждую рекомендацию с ошибкой или подтипом параметра; тексты явно демонстрационные.

### 5. Добавить мок-материалы компании
- Показать внутри экрана три демонстрационные карточки по параметру «Закрытие»; это не реальные корпоративные материалы.
- Для каждой карточки хранить поля `title`, `format`, `description`, `url: null`, `clickable: false`.
- Мок-набор для заполнения интерфейса:
  | Название | Формат | Описание | URL |
  |---|---|---|---|
  | «Финальный этап сделки: как договориться о следующем шаге» | Видео, 6 минут | Разбор фиксации решения клиента и договорённости о следующем контакте. | `null` — мок-данные, перехода нет |
  | «Чек-лист закрытия звонка» | Памятка | Короткая проверка: решение, следующий шаг, срок и ответственный. | `null` — мок-данные, перехода нет |
  | «Сильные формулировки для фиксации договорённости» | Подборка примеров | Демонстрационные фразы для перехода от обсуждения к конкретному действию клиента. | `null` — мок-данные, перехода нет |
- Нажатие по карточке/названию ничего не открывает; не использовать фиктивные домены и внешние ссылки.

### 6. Сохранить завершение и историю
- Сохранить кнопку получения размороженных очков при достижении цели.
- Проверить, что успешное завершение обновляет баланс, снимает активный квест и не оставляет на экране устаревшие ошибки/рекомендации.
- Сохранить историю выполненных квестов компактным блоком после деталей активного квеста.


### 7. Проверить адаптивность, доступность и взаимодействия
- Сохранить мобильную компоновку существующего приложения: карточки должны читаться без горизонтального скролла страницы.
- Длинные цитаты, заголовки материалов и названия ошибок должны переноситься корректно.
- Все ссылки и действия должны иметь ясные подписи, видимые состояния фокуса и доступную область нажатия.
- Проверить состояния: активный квест с ошибками, активный квест без ошибок за 7 дней, раскрытый список после «Показать ещё» и завершённый квест. Состояние без активного квеста вне демо-сценария.

### 8. Критерии приёмки
- Блока «Доступные» и возможности взять новый квест с этого экрана больше нет.
- Активный квест и замороженная сумма по-прежнему видны; условие и прогресс понятны без дополнительного объяснения.
- В списке только ошибки параметра «Закрытие» за последние 7 дней; первые 5 показаны сразу, «Показать ещё» раскрывает следующую порцию.
- Карточки ошибок повторяют полезную структуру «Что пошло не так», но не показывают таймкод и не ведут в звонок.
- Ошибки, цитаты, рекомендации и обучающие материалы обозначены как демо-мок-данные; реальные клиентские данные не подразумеваются.
- Есть связанные практические рекомендации и эталонные формулировки по «Закрытию».
- На экране есть три мок-материала с названием, форматом и описанием; URL равен `null`, нажатие ничего не открывает.
- История выполненных квестов сохранена компактным блоком.
- Выполнение квеста по-прежнему возвращает замороженные очки в активный баланс.
- Сценарий отсутствия активного квеста не добавляется.
